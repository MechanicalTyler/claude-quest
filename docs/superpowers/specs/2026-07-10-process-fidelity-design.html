Design: Process Fidelity Gate

Story: sc-1201 · Repo: claude-quest (plugins/dev-workflow) · Date: 2026-07-10

Problem

full-cycle and its stage skills sometimes decide, on their own, to skip a documented step (write-spec, the User Approval Gate), reorder the pipeline, or weaken a gate (CI/deploy exemption, Loop Safety Guard) without asking. Prose rules that are only descriptive get skimmed past under time pressure or when a step looks "obviously" redundant. This design adds an explicit, salient permission-ask requirement that models the existing Story Creation Gate, which already proves this pattern works in this codebase.

Precedent

Commit 998f9db ("add subagent wait discipline to stop orchestrator idling") solved a structurally identical problem — skills silently doing the wrong thing at a dispatch point — with exactly this shape: one mandatory section added to shared/standards.md, plus short pointers back to it from every real call site (full-cycle, epic, review-pr). This design reuses that shape rather than inventing a new one.

Chosen approach

Single canonical rule in shared/standards.md (one source of truth, read by every dev-workflow skill at session start) plus a one-line pointer at each concrete decision point where a skip/reorder/ignore could actually happen. Rejected alternative: restating the full rule text inside each of the five files — rejected because duplicated prose drifts out of sync over time (the same reason the Story Creation Gate isn't copy-pasted either).

New standards.md section

Add "Process Fidelity (no undocumented deviation)", placed immediately before the existing Story Creation Gate section — Story Creation Gate is itself a specific, pre-existing instance of this same general principle, so the general rule reads naturally right above its first concrete example.

Required content of the new section:

  • Scope: covers skipping any documented step, reordering the documented stage sequence, weakening or bypassing any documented gate (User Approval Gate, CI gate, deploy gate, Loop Safety Guard, Story Creation Gate), and ignoring any standard in standards.md or a skill's own SKILL.md.
  • Ask first, always: before any such deviation, stop and ask the user for explicit permission, stating exactly what would be skipped/reordered/ignored and why. Proceed only on an explicit yes — including when the deviation looks obviously safe, faster, or redundant in the moment. "This seems unnecessary here" is a reason to ask, not a reason to skip.
  • Autonomous / subagent contexts (no ability to ask): never deviate. Stop and report what would need to be skipped and why, the same way the Story Creation Gate already handles this case for autonomous story creation.

Explicitly out of scope

address-pr-comments and epic are not touched — the approved story acceptance criteria name exactly the five files above plus standards.md. Any equivalent gap in those two skills is a follow-up, not part of this change.

Verification

No build/test step exists for this plugin (markdown + one HTML asset, no compiled code). Verification is: read the five files back and confirm the new rule text is present, consistently worded, cross-references standards.md, and doesn't duplicate or contradict the Story Creation Gate, User Approval Gate, Loop Safety Guard, or CI/deploy exemption logic it sits next to.
